## Standalone launcher, settings and runtime

The standalone route now has an x86 `dinput8.dll` and `launch.exe`, plus an x64 `settings.exe` with static raylib 5.5.
SDL 3 handles controllers through its enabled HIDAPI, XInput, RawInput, DirectInput, Windows Gaming Input and virtual
backends. The GameInput C++ backend is excluded. This work is in `standalone/`; CamLab itself was not changed.
Authoritative usage and architecture: [standalone README](../../standalone/README.md),
[build notes](../../standalone/BUILD.md), [investigation](../../standalone/INVESTIGATION.md).

- Settings cover a 3840 x 2160 fullscreen, 60 Hz, vsync profile, English/free-play/HUD options and sound levels
  80/70/80. Default pad mapping is left-stick steering, R2/L2 throttle/brake, Options start, Cross view, R1 handbrake,
  right-stick up shift-up and left shift-down, Create coin. Default bindings are omitted from the saved YAML.
- The settings file is deliberately a small schema: two-space indentation, scalar values, single-quoted strings,
  booleans and integers. Unknown and duplicate keys are rejected. It is not a general YAML parser, and the current
  ANSI-path limit remains. Saving is atomic with a `.bak`; external edits require Reload, unsaved changes have a
  dialog, Ctrl+S saves and Ctrl+Enter launches. XML import preserves the source and an import report; unsupported
  active options fail instead of disappearing. Force feedback, haptics and linked cabinets are not implemented.
- Overlay creation copies by default. Optional hardlinks/junctions require materializing assets before editing;
  source hashes protect the private source tree, and existing destinations/reparse points are rejected.
- `sr3mods_start(const char *absolute_settings_path_utf8)` is the explicit `__cdecl` runtime entry point:
  0 success, 1 invalid settings, 2 incompatible bytes, 3 internal failure. It is dispatched after creation of
  `RacingClass`, outside DllMain. The adjacent DLL and an external attaching executable are mutually exclusive
  routes. Existing patch selections are preserved when camera/mod/watchdog options change.
- Camera logic and the live loop share native patch code. The final names are `sr3mods.dll`, `sr3mods.exe`,
  `sr3mods.ps1`, `watchdog.exe` and `watchdog.ps1` (`b188f89`). The native watchdog hosts PowerShell without a separate
  PowerShell child; it supports detach/reattach and the common recorder path. GDI fallback was removed.

Native watchdog, SDL virtual-device and lifecycle tests use stand-ins or saved fixtures. A real 4K boot and readback
were demonstrated, but a full race and a physical DualSense session remain unverified. The latest watchdog controls
still need visual review. A terminal-versus-interactive launcher context failure was recorded; its exact cause was
not established. These are not closed by importer or mock-runtime tests.

### Reproduced attract/demo shutdown crash: fixed

The access violation at `0x586F74` occurred after 110 seconds idle with mods both enabled and disabled, without
requiring Windows Graphics Capture. The cause was a stale System_GHeap texture descriptor (`0x8134E0`, registry
row 4), not a demonstrated camera-mod or capture failure. Texture rebuild at `0x631CA0` releases the old object at
`0x631D3D`, then updates the registry at `0x631DE2` and only the current descriptor at `0x631DE6`. Software sharing
at `0x5862E4`/`0x58633D` creates other descriptors without COM AddRef; those aliases retained the released pointer.

The `texture_rebind` hook synchronizes all matching type-5 aliases in the fixed pool while preserving original
stores, pushed argument, registers, flags and reference counts. It is guarded by executable identity and the six
expected instruction bytes. A native test executes the actual hook. The opt-in no-mods comparison and the final
default-mods run both survived the 110-second idle/Escape scenario, exit code 0 and no dump (software refs 2).
`9aee814` fixes this reproduced regression; `a163b24` records the result. This does not establish every possible
shutdown path or full-race stability. Evidence folders are `exit-rebind-test`, `exit-rebind-mods-test` and `exit-ab-long`.

The earlier blue 4K boot readback was 33,177,600 bytes. A capture at 15 seconds succeeded after earlier 6-12.75-second
timeouts; the first-present probe measured 16 ms. That early boot gap was not evidence that the capture hook was absent.

## Reproducible source builds and release layout

The standalone build uses one x64 GNU compiler with `-m32` for the x86 components, a custom CRT entry and
`-nostdlib`. OS import libraries are generated from export names; OS DLL bytes are not shipped. The standard-Python
builder needs no Git, CMake, Visual Studio or downloads during the build. SDL 3.4.16 and raylib 5.5 inputs are pinned;
source/dependency/compiler/header hashes, `-MD` dependencies and linker trace inputs support the cache and provenance.
An x86 DLL size regression came from `-fdata-sections` producing `.bss.*` not collected by the custom layout; using
normal BSS fixed it. See the build notes for exact pins and commands rather than copying moving build recipes here.

The source-only mod and optional toolchain are separate archives. Release tooling rejects binaries in the mod,
checks source links before staging, and can run the staged stack against v15. The current source-distribution choice
is `SOURCES.txt` links to exact upstream archives and WinLibs recipes, with license texts; the earlier proposed source
ZIP was superseded. This describes the implemented packaging, not a new legal assessment. Compiler closure work
also covered the x86 standalone route (`3f0fd27`, `f61d10d`), with hash-verified dependencies. The importer still needs
the packaged NumPy/Pillow versions; no final smaller NumPy-free release size was demonstrated.

The public stack, layout, step naming, exports and thread controls were integrated in `365baaf`, `1dfdd55`, `5a4138f`,
`55729ee` and `6aa25d3`. Online setup/pins and release corrections include `93a10b8`, `1f3a906`, `665c4fd` and `f61d10d`.
The packaged GCC 13.2.0 closure and checked online GCC 14.2.0 are distinct configurations; [30](30_import_stack.md)
records the checks. Blanket `-ffp-contract=off` on all existing helpers changed output; it is applied per port where
the original arithmetic requires it, not imposed globally.
